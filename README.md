# Projector

## About
A game that lets users create a 2D platformer game using 3D objects.

On first load, users will go through a series of landing pages.

The game environment is a physical room. Users will select objects off a table, arranging them however they want before a white screen.

Then, when time is up, the casted shadows of these objects will become physical objects in the 2D platformer game.

Users will be loaded into this 2D environment to race, collecting points for various actions. At the end of the race, a winner will be selected and displayed. Then, they can return to the initial landing page(s).

## Technology
We are developing using XR Toolkit and ProBuilder, for Meta Oculus 3.

Multiplayer uses Netcode for GameObjects with Unity Multiplayer Services (Lobby + Relay). Players sign in anonymously; the host creates a private session of up to 4 players, and others join with its 6-character code. Lobby and Relay must be enabled for the project in the Unity Cloud dashboard.

## Scene flow

| Scene | What it is |
| --- | --- |
| `LandingMenu` | First load, at an old movie theater's concessions stand: posters over the counter for the build / project / race / play steps, a popcorn machine, and a framed poster of runners racing to the finish. The menus stand at the counter. **Host private game** (join by code), **host public game** (also findable by **join random game**), **join game with code** (keypad). Then the game-found screen: live code and players; only the host gets **START GAME**. |
| `ProjectorRoom` | The game itself, all in one room (below). |

In the projector room:

1. **Build.** Grab an item off the table (grip), move it into the projector's beam, then hold it steady for 2 seconds to confirm and lock its placement. Small hand motion is tolerated. Items cannot overlap: an invalid item turns red and returns to its last clear pose if released, while a valid confirmation fills yellow. The projector shows a live, stylized 2D drawing of every placed item on the theater screen. You have 90 s, or pull the rope beside the screen (or press the projector's first button); the square of light by the rope says what a pull does.
2. **Race.** The drawn shapes lock in as platforms with a coin over each, and everyone races on the screen: left thumbstick runs, A jumps. Points: 1000/750/500/250 by finish place, +100 per coin, -50 per fall. The host can pull the rope to end the race early.
3. **Results** are projected on the screen. The host pulls the rope to play again (back to building, props where they were); everyone else pulls it to leave.

At any point, pulling the rope twice in quick succession leaves: the curtains' ties drop, the curtains slide shut over the screen, and you're taken back to the lobby.

The projector films an off-screen 2D stage with an orthographic camera; the wall shows that image through `Projector/Projection Screen` (hotspot falloff, soft focus and glow, color fringing, scanlines, flicker, dust).

The host's scene changes are synced to every player. Leaving, or the host closing the game, returns players to the landing menu.

Scenes are generated by editor scripts under the **Projector** menu. **Build All Game Scenes** rebuilds the network prefabs and landing menu objects and re-adds the game to the projector room (the room itself, an old movie theater, is built by **Build Quest Room Scene**). **Build Quest APK** writes `Builds/Projector.apk`; install it on each headset with `adb install -r Builds/Projector.apk`.

## AI Usage

**1. Did each of you use AI as a personal assistant, or as a shared team member?**
As a team member. We came up with the ideas and design; the AI implemented the code and scene elements, and we reviewed, tested on the headset, and merged its work through our shared repo.

**2. Roughly how many and which AI systems did you use?**
Two: Claude (Claude Code) and Codex.

**3. When did you start something in Unity for the AI to finish, vs. give a prompt and let the AI start the work?**
- *We started, AI finished:* Jason built the first landing, join-by-code and host menus, and the AI later wired them to real Multiplayer sessions. We imported the Quaternius food pack ourselves, and the AI placed it as table props. We tested on the Quest and reported problems (e.g., the boundary at the table) for the AI to fix.
- *Prompt first, AI started:* the projector room, the whiteboard, item placement/overlap rules, networking, and the game loop. The AI writes editor scripts (the **Projector** menu) that generate the scenes, so the work begins from a prompt rather than from hand-built scenes.

**4. Example prompts**
- "The front wall should have a minimalistic board, white-board style. Empty for now."
- "I want to reach the table and be able to pick up stuff."
- "Please complete this four-part issue: [GitHub issue link]. Item-item interactions means items should not overlap with each other."
- "Confirm that the intro screen to project room transition is still working."

**5. How are you connecting your AI with Unity?**
Through a CLI/desktop agent working directly in the project folder: Claude Code and Codex edit the C# scripts and assets, run git, and use the Unity CLI. Unity then runs the AI-written editor scripts to build the scenes and the Quest APK. We tried MCP for Unity but removed it.
